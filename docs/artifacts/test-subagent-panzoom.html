🛡️ สถาปัตยกรรมระดับองค์กร (Enterprise Architecture)

สถาปัตยกรรมระบบประมวลผลการชำระเงินแบบ 3 ชั้น

ผังแสดงการทำงานของระบบประมวลผลธุรกรรมทางการเงินความเร็วสูง (High-Throughput Payment Processing Engine) พร้อมกลไกตรวจสอบความถูกต้อง การป้องกันทุจริต และระบบบัญชีแยกประเภทแบบ ACID

ชั้นที่ 1: Ingress & Edge
TLS & Rate Limit
ตรวจสอบ JWT Token และป้องกันการโจมตี DDoS ด้วย Envoy Gateway
ชั้นที่ 2: Core Orchestration
Saga & Risk Engine
จัดการ State Machine แบบกระจายศูนย์ พร้อมวิเคราะห์ความเสี่ยงแบบเรียลไทม์
ชั้นที่ 3: Settlement & Data
ACID & Idempotent
บันทึก Ledger ลง PostgreSQL และเชื่อมต่อเครือข่าย PromptPay / Visa

⚙️ คำอธิบายเชิงสถาปัตยกรรม (Architectural Deep-Dive)

ระบบประมวลผลการชำระเงินได้รับการออกแบบตามมาตรฐานความปลอดภัยระดับสูง เพื่อรองรับปริมาณธุรกรรมจำนวนมากพร้อมกัน (High Concurrency) โดยรักษาคุณสมบัติความถูกต้องของข้อมูล (Data Consistency) และป้องกันการตัดเงินซ้ำซ้อน 100% ผ่าน 3 ลำดับชั้นหลัก:

1. การควบคุมช่องทางเข้าถึงและความปลอดภัยรอบนอก (Client & Ingress Tier)

ทุกคำขอชำระเงินจากแอปพลิเคชันมือถือหรือเว็บ จะส่งผ่านช่องทางเข้ารหัส TLS 1.3 มายัง API Gateway โดยระบบจะดำเนินการตรวจสอบความถูกต้องของโครงสร้าง Payload และส่ง Token ไปตรวจสอบสิทธิ์กับ Auth Service ก่อนอนุญาตให้คำขอเข้าสู่เครือข่ายภายใน พร้อมทั้งมีระบบ Rate Limiting เพื่อป้องกันการส่งคำขอถี่เกินขีดจำกัด

2. การบริหารจัดการสถานะและตรวจสอบความเสี่ยง (Core Business & Orchestration Tier)

หัวใจหลักของระบบคือ Payment Orchestrator ซึ่งทำงานร่วมกับ State Machine แบบกระจายศูนย์ตามแนวคิด Saga Pattern เมื่อได้รับคำขอ ระบบจะส่งข้อมูลให้ Fraud Detection Engine วิเคราะห์พฤติกรรมผิดปกติและคำนวณ Risk Score ทันที หากมีความเสี่ยงต่ำ ระบบจะดำเนินกระบวนการตัดเงินต่อ พร้อมกระจาย State Change Events ไปยัง Kafka Event Stream เพื่อให้ระบบวิเคราะห์ข้อมูลและแจ้งเตือนทำงานแบบ Asynchronous ต่อไป

3. การตัดเงินปลายทางและการบันทึกบัญชีแยกประเภท (Data & Settlement Tier)

ก่อนส่งคำขอไปยังระบบธนาคาร ระบบจะสร้าง Distributed Lock บน Redis Cache โดยอ้างอิงจาก Idempotency Key เพื่อรับประกันว่าจะไม่มีการส่งคำขอตัดยอดซ้ำ เมื่อระบบ External Bank Switch ตอบรับผลการชำระเงินสำเร็จ ระบบจะทำธุรกรรมแบบ ACID ลงใน PostgreSQL เพื่อบันทึกบัญชีแยกประเภท (Double-Entry Ledger) และ Audit Log อย่างสมบูรณ์

📊 สรุปคุณสมบัติและการทำงานแยกตามลำดับชั้น

ชั้นสถาปัตยกรรม คอมโพเนนต์หลัก โปรโตคอล / รูปแบบการสื่อสาร หน้าที่และความรับผิดชอบ มาตรการความปลอดภัย
Tier 1: Ingress API Gateway, Envoy Proxy, Auth Validator HTTPS / TLS 1.3, JSON, JWT รับคำขอ, ตรวจสอบความถูกต้องของสิทธิ์ และจำกัดปริมาณทราฟฟิก WAF, DDoS Protection, JWT Signature Verification
Tier 2: Core Payment Orchestrator, Fraud Engine, Kafka gRPC (Protobuf), Event Streams ควบคุม State Machine ธุรกรรม, ตรวจสอบทุจริต และกระจายอีเวนต์ Mutual TLS (mTLS), Risk Scoring Rule Engine
Tier 3: Data PostgreSQL DB, Redis Cluster, Bank Switch ISO 8583, REST Switch API, SQL (ACID) ตัดเงินผ่านธนาคาร, ป้องกันคำขอซ้ำ และบันทึกบัญชีแยกประเภท Idempotency Lock, Double-Entry Ledger, Encryption at Rest
