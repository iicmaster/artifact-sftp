EVENT-DRIVEN ARCHITECTURE · ENTERPRISE

สถาปัตยกรรม Event-Driven ระดับองค์กร

API Gateway รับคำขอและส่ง Event เข้า Kafka Event Bus จากนั้น Order Worker และ Payment Worker ประมวลผลแยกอิสระ ก่อนบันทึกผลลง Database Cluster ด้วยธุรกรรมที่ตรวจสอบย้อนกลับได้

เส้นทางข้อมูลหลัก
API → Event → Worker → DB

แยกการรับคำขอออกจากงานเบื้องหลัง เพื่อให้แต่ละส่วนขยายตัวได้ตามภาระงาน

รูปแบบการประมวลผล
Asynchronous

Kafka เก็บ Event ตาม Topic แล้วกระจายให้ Worker ที่รับผิดชอบแต่ละโดเมน

หลักประกันข้อมูล
Idempotency + ACID

Worker กันงานซ้ำ และ Database Cluster ยืนยันผลด้วยธุรกรรมที่ครบถ้วน

วิธีอ่านแผนผัง

ระบบรับคำขอที่ API Gateway เพียงจุดเดียว จากนั้น Gateway ส่ง Event เข้า Kafka แทนการเรียก Worker โดยตรง Kafka จึงทำหน้าที่เป็นขอบเขตคั่นกลางระหว่าง Request ที่ต้องตอบเร็วกับงานเบื้องหลังที่ใช้เวลานานกว่า

เส้นทางคำสั่งซื้อ

Order Worker อ่าน Event จาก Topic ของคำสั่งซื้อ แล้วตรวจสอบ Idempotency ก่อนบันทึกสถานะลง Database Cluster การแยก Consumer Group ทำให้เพิ่มจำนวน Worker ได้โดยไม่ต้องปรับ API Gateway

เส้นทางการชำระเงิน

Payment Worker อ่าน Event ของการชำระเงินแยกจาก Order Worker ระบบกำหนด Retry ที่ปลอดภัยและเขียนผลด้วยธุรกรรม ACID เพื่อไม่ให้การลองใหม่สร้างรายการชำระเงินซ้ำ

จุดควบคุมที่ต้องรักษา

  • API Gateway: ตรวจสอบ Token, จำกัดอัตราคำขอ และปฏิเสธ Payload ที่ไม่ตรง Schema ก่อนเข้าเครือข่ายภายใน
  • Kafka Event Bus: กำหนด Topic, Retention และ Consumer Group ให้สอดคล้องกับอายุของข้อมูลแต่ละโดเมน
  • Order / Payment Worker: ใช้ Idempotency Key, Dead-Letter Queue และ Retry Policy ที่ตรวจสอบได้
  • Database Cluster: แยก Primary กับ Replica พร้อม Audit Log เพื่อรองรับการตรวจสอบย้อนหลังและการกู้คืน

หลักการออกแบบ

ถ้า Kafka ช้าลง Gateway ยังรับคำขอได้ตามขอบเขตที่กำหนด ถ้า Worker หยุดทำงาน Event ยังอยู่ใน Log และกลับมาประมวลผลต่อได้ ขอบเขตเหล่านี้ช่วยลดการผูกกันแน่นระหว่างบริการและทำให้วิเคราะห์เหตุขัดข้องได้ตรงจุด

สรุปความรับผิดชอบของแต่ละคอมโพเนนต์

คอมโพเนนต์ หน้าที่หลัก ขอบเขตความรับผิดชอบ
API Gateway รับ Request และส่ง Event Authentication, Rate Limit และการตรวจ Schema
Kafka Event Bus เก็บและกระจาย Event Topic, Retention และ Consumer Group
Order / Payment Worker ประมวลผลตามโดเมน Idempotency, Retry และการเปลี่ยนสถานะ
Database Cluster เก็บผลลัพธ์ทางธุรกิจ ACID Transaction, Replica และ Audit Log

คำศัพท์เทคนิคคงรูปแบบสากลไว้ เพื่อให้ค้นต่อในเอกสารระบบและ Source Code ได้ตรงกัน
