อธิบายให้คนที่ยังไม่เคยเห็นมันเลย

artifact-sftp คืออะไร

คุณมีไฟล์ HTML หนึ่งไฟล์ในเครื่อง — มันพาไฟล์นั้นไปอยู่บนเว็บของคุณเอง ที่ลิงก์ซึ่งไม่เปลี่ยน

แค่นั้น ที่เหลือคือรายละเอียดว่ามันระวังอะไรระหว่างทาง

สิ่งที่มันไม่ใช่: มันไม่ใช่บริการโฮสต์ มันไม่มีเซิร์ฟเวอร์ให้คุณ คุณต้องมีบัญชี SFTP กับเว็บเซิร์ฟเวอร์ของตัวเองอยู่แล้ว — มันคือคนส่งของ ไม่ใช่โกดัง

เส้นทางของไฟล์หนึ่งไฟล์

1

คุณเขียนไฟล์ .html หนึ่งไฟล์

ไฟล์เดียว จบในตัวเอง CSS กับ JavaScript อยู่ข้างในหมด ไม่ดึงของจากที่อื่น

↓
2

เก็บสำเนาไว้ในเครื่องก่อนก่อนส่ง

ลงใน docs/artifacts/<tool>/<visibility>/<slug>/ ทั้งไฟล์ปัจจุบันและสำเนาที่ปั๊มเวลาไว้ — ถ้าอัปโหลดล้มทีหลัง ของยังอยู่ครบ

↓
3

สแกนหาความลับที่หลุดมา

ถ้าเจอรูปแบบที่เหมือนคีย์หรือรหัสผ่านฝังอยู่ในไฟล์ มันหยุด ไม่ส่ง

↓
4

อัปโหลดผ่าน SFTP

ตรวจลายนิ้วมือของเซิร์ฟเวอร์ก่อนคุย (host key pinning) — เจอเครื่องแปลกปลอมแล้วไม่ยอมส่ง

↓
5

ตรวจว่าถึงจริงและถึงถูกตัว

เทียบ SHA-256 ว่าไบต์บนเซิร์ฟเวอร์ตรงกับในเครื่อง แล้วลองเปิดแบบไม่ล็อกอิน เพื่อยืนยันว่าของ private ไม่ได้โผล่ให้คนทั่วไปเห็น

สามอย่างที่ scp ธรรมดาไม่ทำให้

🗂️

ทับแล้วของเก่าไม่หาย

ทุกครั้งที่ส่ง มันเก็บสำเนาแยกพร้อมเลขเวอร์ชันและเวลาไว้ข้าง ๆ ตัวปัจจุบัน ย้อนดูได้ว่าเมื่อวานหน้าตาเป็นยังไง

🔒

เงียบไว้ก่อนเป็นค่าเริ่มต้น

private คือค่าตั้งต้น จะทำให้เป็นสาธารณะต้องสั่งเพิ่มอีกชั้นหนึ่งโดยเฉพาะ พลาดแล้วหลุดยาก

✋

ไม่เชื่อว่า "ส่งแล้ว" แปลว่าสำเร็จ

มันไปอ่านกลับมาเทียบไบต์จริง ๆ คำว่าสำเร็จของมันคือเทียบแล้วตรง ไม่ใช่คำสั่งจบโดยไม่มี error

ลิงก์ที่ได้ ประกอบด้วยอะไร

https://เว็บของคุณ/claude/private/my-report/
tool — ผู้ช่วยตัวไหนเป็นคนส่ง: codex, openclaw หรือ claude
visibility — private หรือ public แยกกันคนละโฟลเดอร์ ไม่ปนกัน
slug — ชื่อที่คุณตั้ง ขึ้นต้นด้วยตัวพิมพ์เล็กหรือตัวเลข ตามด้วยตัวพิมพ์เล็ก ตัวเลข หรือขีดกลาง รวมไม่เกิน 63 ตัว

เครื่องมือที่มีให้เรียก มีหกตัว

เครื่องมือทำอะไร
artifact_sftp.setup_statusพร้อมส่งหรือยัง — คอนฟิกครบไหม ต่อเครื่องปลายทางติดไหม
artifact_sftp.setupบอกว่าต้องเตรียมอะไรเพิ่ม ไม่รับรหัสผ่าน ไม่รันตัวติดตั้งให้
artifact_sftp.publishส่งไฟล์ขึ้น ต้องสั่ง confirm เสมอ ถ้าจะให้เป็นสาธารณะต้องสั่ง confirm_public เพิ่มอีก
artifact_sftp.unpublishเอาลงจากเซิร์ฟเวอร์ — สำเนาในเครื่องยังอยู่เสมอ
artifact_sftp.readอ่านสำเนาในเครื่อง ไม่ใช่ไปดึงจากลิงก์
artifact_sftp.listดูว่ามีอะไรเคยส่งไปแล้วบ้าง และมีร่างอะไรค้างอยู่

ทำไมลิงก์ private ถึงอ่านไม่ได้: มันเป็นลิงก์สำหรับคนเปิดดู ที่มีด่านกั้นอยู่ข้างหน้า ไม่ใช่ที่อยู่สำหรับให้โปรแกรมไปดึงข้อมูล อยากอ่านเนื้อหาต้องใช้ artifact_sftp.read กับสำเนาในเครื่องแทน

สิ่งที่ภาพนี้ไม่ได้วาด

  • การตั้งค่าตอนเริ่มต้น — ไฟล์คอนฟิกอยู่นอกโปรเจกต์ ตั้งสิทธิ์ไว้แคบ และผู้ใช้เป็นคนกรอกเอง ผู้ช่วย AI ไม่แตะ ไม่ถาม ไม่ส่งต่อ
  • วิธียืนยันตัวตนสามแบบ — รหัสผ่าน, SSH key หรืออ้างอิงคีย์จาก 1Password ภาพนี้รวบให้เหลือกล่องเดียวว่า "อัปโหลด"
  • ข้างในตัวส่งจริง — ขั้นตอนที่ 2 ถึง 5 เกิดในสคริปต์ตัวเดียวกัน ภาพนี้แยกให้เห็นเป็นห้าก้อนเพื่อให้ตามทัน ไม่ใช่เพราะมันเป็นห้าโปรแกรม
  • กติกาว่าใครเรียกอะไรได้ — ผู้ช่วย AI ต้องเรียกผ่านเครื่องมือหกตัวข้างบนเท่านั้น ห้ามไปเรียกสคริปต์ข้างในตรง ๆ ห้ามหาทางอื่นส่งแทน
ภาพนี้อธิบายพฤติกรรมที่อ่านจากซอร์สจริงในโปรเจกต์ — ไม่ใช่จากแผนที่ตั้งใจไว้ · ชื่อเครื่องมือ เส้นทางโฟลเดอร์ และค่าตั้งต้นทุกตัวใช้ชื่อจริงตามที่โค้ดใช้
